Project: AccessZero
Identity Breach Containment & Access Revocation Platform
One-line idea

AccessZero allows an IT administrator to instantly determine and eliminate everything a compromised employee can access across an organization's identity infrastructure.

Think:

"What can this person access right now, and if their account is compromised, can I kill that access everywhere in seconds?"

That is the product.

Not an IAM clone.

Not an SSO demo.

Not a user-management system.

Why this is a serious IT-admin problem

Imagine an employee:

Employee: Rahul
Department: Finance

Their identity may have access to:

                    Rahul
                      │
          ┌───────────┼───────────┐
          ↓           ↓           ↓
       Keycloak     LDAP       Azure AD*

     ┌────┼────┬────────┐

   Jira GitLab VPN   Internal App
     │
     ↓

Now suppose Rahul's credentials are compromised.

The IT admin needs to answer:

"What can Rahul access?"

and then:

"How do I shut all of it down immediately?"

Normally this can involve:

disabling the account
removing LDAP groups
revoking OAuth tokens
terminating sessions
invalidating refresh tokens
removing application assignments
terminating SSO sessions
disabling service access
checking active sessions
checking inherited permissions

That is where AccessZero comes in.

Step 4 — SAML containment

For SAML-connected applications, AccessZero tracks the identity's application assignments and supported logout/session mechanisms.

Important: SAML doesn't provide a universal "revoke every session everywhere" mechanism, so your project should explicitly model the difference between:

Identity disabled
Session terminated
Application access revoked
Application requires local session expiry

That nuance makes the project more realistic, not less.

Identity Graph

This is probably the most technically interesting component.

AccessZero builds a graph:

USER
 │
 ├── GROUP
 │     │
 │     └── ROLE
 │           │
 │           └── APPLICATION
 │
 ├── SESSION
 │
 ├── TOKEN
 │
 └── SAML ASSIGNMENT

Example:

Rahul
 │
 ├── Finance
 │     └── PayrollAdmin
 │            └── Payroll System
 │
 ├── Engineering
 │     └── GitLab
 │
 └── VPN Users
        └── VPN

Then the system calculates:

USER → GROUP → ROLE → APPLICATION

and

USER → TOKEN → APPLICATION

and

USER → SESSION → APPLICATION

That's how you calculate the access blast radius.
